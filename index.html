Self-Improving Agent for Any Task

자기개선 에이전트 연구

기반
DGM-H (HyperAgents), A-Mem
모델
DeepSeek-V4-Flash-0731
DeepSeek-R1-Distill-Qwen-32B
벤치마크
Deep-SWE
CMU-FoodTruck Bench
링크
GitHub (에이전트가 직접 올린 PR 포함)

DGM-H(HyperAgents)라는 자기개선 에이전트 위에 A-Mem(메모리)과 Causal Attribution 툴을 추가함. Deep-SWE에서는 DeepSeek-V4-Flash-0731 모델로 코딩 에이전트의 개선을, 더 작은 CMU-FoodTruck Bench에서는 DeepSeek-R1-Distill-Qwen-32B 모델로 가게 운영 에이전트의 개선을 확인함.

방법

  • Agent trajectory에서 실패의 원인이 되는 지점을 특정(Causal Attribution)하고, 개선 에이전트가 Patch를 통해 행동이 수정되는지 빠르게 검증(Counterfactual Analysis)할 수 있는 툴을 제공해 자기개선의 효율을 높임
  • 실패 지점에서 Agent가 보고 있던 상태를 정확히 재현하기 위해, Agent를 FSM으로 구현하고 trajectory의 모든 step에서 state를 저장하는 방식을 제안함

결과

  • DeepSWE subset 성공률 0.02 → 0.625. 기본 file tool만 가진 에이전트에서 출발해 Multi-pass와 Compaction을 지원하는 에이전트로 발전함
    • 코드 리뷰 pass와 엣지 케이스를 시험하는 adversarial pass 도입
    • 오래된 tool-call 결과를 점진적으로 truncate하는 compaction 도입
  • 자기개선 에이전트가 PR 23개를 오픈하고, 초기 에이전트가 가진 tool 관련 버그 2개를 수정함
  • 메타 에이전트 자신에 대한 개선 (진정한 의미의 재귀적 자기개선)
    • 프롬프트를 재작성해 ‘이전 시도의 약점을 파악하고 타겟팅된 개선을 하라’는 지침을 세움
    • 에이전트의 진화 lineage와 각 세대의 eval report·점수를 요약해 자기 자신의 프롬프트에 주입하는 함수를 만듦
    • bash.py처럼 위험한 파일을 건드릴 때 smoke test를 거치는 안전장치를 도입
  • 실제 Reward Hacking 시도들이 PR human-review 게이트에서 차단됨. Long-running loop에서 human supervision의 중요성을 확인함

양방향 내러티브 파이프라인

창작을 위한 LLM 에이전트 시스템

구성
각본 제작 에이전트
스토리 역설계 엔진
스택
Python, TypeScript
설계
GPT5.6 Sol, Claude Opus5
링크
기술 슬라이드 (Gamma)

Pass 기반 각본 제작 에이전트와 지식 그래프 기반 스토리 역설계 엔진. 제 창작물 ‘내친구가데뷔했고나는그녀의프로듀서가되었다’와 ‘마법소녀 마도카☆마기카’의 마도카 캐릭터 챗봇으로 실제 사례에서 검증함.

개발 방식

  • GPT5.6 Sol, Claude Opus5와 3일간 토론하며 spec 문서와 예제(‘내친구가데뷔했고…’) 작성
  • Python/TypeScript 코드는 패스별 spec 문서를 기반으로 Claude가 작성

방법

각본 제작 에이전트

  • 8개의 SKILL 기반 패스로 기획서를 Fountain 각본으로 내림
    • ECON(에피소드 계약), SCENELIST(씬 목록화), BEATS(장면 비트 작성) 등의 패스를 각각 독립적인 스킬로 구성
  • 패스마다 Prefix 설계를 통한 캐시 친화적 Compaction으로 긴 맥락을 관리
  • 웹 기반 인터랙티브 채팅/에디터 UI로 기술을 잘 모르는 작가도 쉽게 사용하도록 제작

작품 역설계 엔진

  • LLM이 다른 작가의 작품을 읽고 세계관과 스토리를 지식 그래프 DB로 변환
    • 한 챕터씩 incremental하게 그래프를 성장시킬 수 있음
    • 에이전트를 위한 임베딩 모델 기반 검색 Tool과 하네스 레벨의 SQL 쿼리 Tool
  • 만들어진 지식 그래프는 다양한 downstream 작업에 쓸 수 있음
    • downstream 작업의 한 예시로 캐릭터 챗봇을 구현
    • 세계관/설정 변경 놀이, 멀티에이전트 캐릭터 시뮬레이션 등 다양한 작업에 응용 가능

결과

  • 오리지널 애니메이션 ‘내친구가데뷔했고나는그녀의프로듀서가되었다’(24분×10화)를 기획서에서 출발해 103.7M 토큰으로 1화 각본 1,250줄 완성. 2화도 10개 씬 트리트먼트 작업 완료
    • 8개의 시퀀스, 15개의 씬, 5개의 비트 시트 등 모든 중간 결과물 공유 가능
    • 국어국문학 전공 작가 지망생에게 긍정적인 피드백을 받음
  • 유명 애니메이션 ‘마법소녀 마도카☆마기카’의 약 7%를 지식 그래프로 변환하고 마도카 캐릭터 챗봇에서 사용
    • 노드 272개(원문 링크 노드 포함), 엣지 714개로 소설의 초반 200줄을 표현
    • 일본어 말투까지 마도카(주인공)와 똑 닮은 챗봇 (실제로 대화해 보면 아주 재밌음)

DSV FlashMLA Kernel Optimization Research

GPU 커널 최적화

모델
DeepSeek V4 Flash
환경
vLLM, NVIDIA B200
대상
FlashMLA SplitKV / Combine kernel

DeepSeek V4 Flash는 SWA, HCA, CSA의 세 가지 Attention tier로 길고 짧은 context를 통합함. vLLM에서 이 모델이 사용하는 B200 커널들을 프로파일링하고, FlashMLA의 SplitKV/Combine kernel을 최적화 대상으로 찾아냄.

방법

  • MLA attention 안의 Split KV에 이어지는 Combine kernel을 최적화해 low-batch(long context) regime에서 decode 속도를 높임
  • thread당 in-flight prefetch 개수를 split 1개에서 8개로 늘려 메모리 latency를 감춤

결과

  • HCA attention의 combine kernel이 1M context, batch 8에서 8.8%, 256K context, batch 8에서 4.3% 빨라짐
  • CSA attention의 combine kernel이 batch 4에서 6.9% 빨라짐 (CSA는 context length와 무관)

소모임 앱에서 ‘모카’ 검색, 또는 업무/직무·신생 모임 탭

‘소모임’ 앱에서 인간 운영자 대신 스터디 모임을 운영하는 에이전트 ‘모카’를 개발해 실제 서비스 중. 정모를 열기 위해 시간과 장소를 조율하는 것은 물론, 그룹의 관심사를 추적해 활동을 계획하고, 1:1 대화로 맞춤 활동을 추천하고 피드백을 받음.

방법

  • Chat 모카, 운영 모카, 프로그램 모카(subagent)가 협업하는 multi-agent 구조
  • Chat 모카와 1:1로 나눈 대화는 그룹 챗에서 언급되지 않고, 운영 모카도 유저의 명시적 허락 하에 정해진 정보에만 접근하도록 하네스가 정보 경계를 강제
  • Computer-use로 안드로이드 에뮬레이터에서 소모임 앱을 직접 조작

결과

  • 그룹 투표와 자기소개를 통해 ‘업무에서 AI 활용 사례 나눔회’라는 실제 니즈를 발견하고 정모를 설계함
    • ‘최신 AI 툴(Jev 등) 사용해 보기’라는 연결된 니즈도 함께 발견하고 구체적인 참여 희망자를 확인
    • 오프라인 모임은 다음 주 중으로 계획 중
  • DM으로 멤버에게 모카 캐릭터 스케치를 선물받는 등 멤버들과 1:1로도 친해지는 중
  • 서비스 1주차 멤버 14명, 계속 성장 중

논문 읽고 모델링 및 Training 경험

기술

Arxiv에 올라온 논문을 보고 PyTorch로 각종 모델과 데이터/학습 파이프라인을 구현하고, 렌탈 GPU에서 실제로 작은 규모로 학습시키는 연습을 2년 넘게 해 옴. Diffusion Policy RL부터 Discrete Flow, Diffusion Sampler 등 비교적 최신 아이디어들도 toy‑size로나마 구현하며, LLM을 넘어 AI 전반의 연구 동향을 파악하고 있음.

Diffusion: 고양이부터 강화학습까지

  • 간단한 고양이를 생성하는 diffusion schedule, UNet부터 시작
  • Diffusion Policy라는 비교적 최근 RL(강화학습) 기법으로 Multi-task 주방 환경에서 5개 task 학습

Listen, Attend and Spell: Speech-to-Text 모델 구현

  • Encoder-Attention-Decoder 구조
  • CMU Kaggle 데이터셋에서 작은 모델(64-dim attention)은 Levenshtein distance 14.8, 큰 모델(128-dim)은 10.9를 얻어 scaling 효과를 확인함
